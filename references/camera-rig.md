# 机位类型库

摄影机怎么架、怎么动、跟着谁——这是白模唯一无法被参考图替代的东西。参考图管材质光线，白模管这个。

每一种 rig 都是时间的纯函数，写在 `engine/solver.mjs` 里。你在 `scene.json` 里选类型填参数，不写运镜代码。

## 十种 rig

| rig | 现实里对应什么 | 什么时候用 | 关键参数 |
|---|---|---|---|
| `static` | 三脚架锁死 | 让主体在固定构图里运动，观众的眼睛不动。仪式感、观察感 | `pos`、`lookAt` |
| `pan` | 三脚架上摇/俯仰 | 从空镜摇到主体，或从一个人摇到另一个人 | `pos`、`from`、`to` |
| `zoom` | 原地变焦 | **不是推进**。透视关系不变，只是画面被裁——用来做眩晕感、突然的注意力收缩 | `pos`、`lens: [24, 85]` |
| `dolly` | 轨道车推拉 | 真的靠近或远离，透视随之改变，空间感是活的 | `from`、`to`、`lens` 固定 |
| `follow` | 斯坦尼康背后跟拍 | 跟着主体走。**滞后量 × 速度 = 景别距离**，这是它的物理本质 | `target`、`lag`、`height` |
| `lead` | 前置倒退跟拍 | 主体正面对着镜头前进。压迫感、情绪可读 | `target`、`lead`（前方几米） |
| `orbit` | 环绕轨道 | 绕着主体转。角速度恒定是它好看的前提 | `target`、`radius`、`angle`、`height` |
| `crane` | 摇臂升降 | 从人的高度升到俯瞰，或反过来落下 | `from`、`to`、`lookAt` |
| `drone` | 航拍 | 高空大范围移动。和 crane 的区别只在尺度 | `from`、`to`、`lookAt` |
| `topdown` | 正上方垂直俯拍 | 队形、图案、调度。**画面自转靠 `spin`，不是转场景** | `center`、`height`、`spin` |
| `pov` | 主观镜头 / 车载 | 第一人称。相机架在主体身上 | `target`、`eye`、`pitch` |

`shake` 是修饰器，可以叠在任何一个 rig 上：

```json
{ "t": [0, 4], "rig": "follow", "target": "hero", "lag": 2.2, "shake": { "amp": 0.02, "freq": 1.1 } }
```

`amp` 是位移幅度（米）：0.01 是稳定器的余震，0.03 是纪录片手持，0.06 以上是奔跑中的抓拍。它用三条正弦叠出来，同一时刻永远同一个值——**不能用 `Math.random()`，那会毁掉确定性**。

## zoom 和 dolly 是两件事

这是最常被写混的一对，而且混了之后成片一定不对。

- **dolly**：机位真的移动。近处物体的相对位置随之改变，纵深是活的。观众感觉「我走过去了」
- **zoom**：机位不动，只换焦距。透视关系冻结，画面像被裁切放大。观众感觉「我盯住了它」

写 prompt 时也必须区分。Kling 官方专门点出过这条：Camera Language（景别/焦段/景深）≠ 运镜控制（推拉摇移）。`make_prompt.mjs` 生成的描述里会带上「原地变焦，不是机位前推」这样的括号，别删掉。

## 想要某个景别，调的是距离不是形容词

景别不是填出来的，是机位距离和焦段一起算出来的。下面这张表按 1.7m 的人算，数字是**主体占满画面高度所需的距离**：

| 焦段 | 占满画高（特写边界） | 占一半（中景） | 占 20%（全景） | 占 8%（远景） |
|---|---|---|---|---|
| 24mm | 1.7m | 3.4m | 8.5m | 21m |
| 28mm | 2.0m | 4.0m | 10m | 25m |
| 35mm | 2.5m | 5.0m | 12.4m | 31m |
| 50mm | 3.5m | 7.1m | 17.7m | 44m |
| 85mm | 6.0m | 12.1m | 30m | 75m |

公式：`可见高度 = 2 × 距离 × tan(垂直视场角/2)`，垂直视场角 `= 2·atan(24 / (2×焦距))`。

同一个「中景」，24mm 拍出来是 3.4m 外的贴身广角（背景被拉远、人被轻微变形），85mm 拍出来是 12m 外的长焦压缩（背景糊成一片、人是平的）。**选焦段就是选背景关系**，不是选清晰度。

`probe.mjs` 会把每个镜头的实际景别算出来给你，`make_prompt.mjs` 会把它写进 prompt。你不用自己判断。

## 一个镜头里的时长与运动量

- **低于 2.5 秒的镜头站不住**。AI 来不及建立空间关系
- 相机在一个镜头里的位移，落在「每秒 0.3-2 米」这个区间比较安全。低于 0.15 m/s 且主体也不动，`probe` 会判成死时间并报 🔴
- 缓动别只动起点。**把起点往后挪会被 ease-in 全吃掉，末段反而更慢**——要动就动终点。判据：把一段五等分，最后一格的位移贡献要 ≥ 15%

## 多机位切换

在 `shots` 里排两个相邻的镜头，边界就是硬切点。不需要额外声明。

```json
"shots": [
  { "t": [0, 4],   "rig": "follow", "target": "hero", "lag": 2.2, "lens": 28 },
  { "t": [4, 7.5], "rig": "lead",   "target": "hero", "lead": 3.6, "lens": 35 }
]
```

三条实证：

**1. 切点会被精确执行。** 2026-08-16 逐帧核对：白模切点 3.967/8.467/11.967s → 成片 3.958/8.458/12.000s，误差小于 1 帧。白模 30fps、成片 24fps，跨帧率照样对得上。

**2. 相邻镜头的景别要拉开。** 中景切中景，观众读不出「切了」，只会觉得画面抖了一下。景别至少跳一档，或者机位方位变化超过 30 度。

**3. 白模可以当剪辑指令用。** 这是 2026-08-14 撞出来的：原计划下载三个机位再本地剪，上传管线卡死，只好把两条白模录制同时连给一个视频节点、在 prompt 里写「0-5 秒用素材 1 的机位，5-8 秒硬切素材 2」——Seedance 一次执行成功，两个角色跨机位外形完全一致。**多机位不一定要在白模里拼好，也可以让 prompt 去调度。**

## 几个常用的组合

| 想要的效果 | 怎么排 |
|---|---|
| 库布里克式走廊跟拍 | 单个 `follow`，`lag` 恒定、`height` 0.5-1.0m、24-28mm，全程绝对匀速无 `shake`。压迫感来自机械般的恒定，加一点晃动就毁了 |
| 街舞 battle | `orbit` 贴身环绕（角速度恒定）→ 末段 `crane` 果断拉升。前紧后放的反差就是高潮结构 |
| 三十年代歌舞片 | `topdown` + `spin`，队形从聚拢到绽放。注意队形半径要塞得进画面（见下） |
| 追逐戏 | `follow` 带 `shake` → 硬切 `lead`（正面看到他的脸）→ 硬切 `static` 低机位（他从镜头前冲过） |
| 产品展示 | `orbit` 慢速环绕 + 中长焦，或 `dolly` 贴面掠过。别用 `shake` |
| 情绪独白 | `static` 或极慢 `dolly` 推进，50-85mm。让主体在画面里几乎不动，靠景别缓慢收紧 |

## 三个把白模做废的坑

**主体不能站着不动。** 白模是给 AI 的运动控制信号，杵在那儿等于没给信号。

**主体不能太小。** 实证：某段人物只占画高 5%、位移只占全程 4%，成片里最后 4 秒人整个消失，只剩空祭坛。加强提示词也救不回来，根因在白模。判据：**占画高低于 10% 且该段位移低于 0.5 个身高，AI 就有很大概率把它丢掉。**

**队形半径受机位高度限制。** 垂直可见半径 = 机位高度 × tan(视场角/2)。12m 高、35mm，只能覆盖 4.1m 半径——把队形排到 6m 外，永远拍不全。`probe.mjs` 里填 `meta.formationRadius` 就会自动检查这条。

这三条 `probe.mjs` 都会在渲染前报出来。但它只查得了几何，查不了「好不好看」——**渲完仍然要抽帧看**。
