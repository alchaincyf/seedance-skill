# 产线 D · 照片反解白模

用户丢来一张照片：「我要这个场景动起来。」

这条产线做的事是：**从照片反解出它的三维空间和相机参数，重建成白模，然后在这个空间里设计运镜。**

## 先说清楚它不是什么

它不是三维重建。不生成网格、不做深度估计、不调任何重建模型。

**因为白模根本不需要那种精度。** 白模只提供三件事——空间关系、运镜路径、时间节奏。官方演示里的白模是几个白圆锥当树、一个红方块当角色，成片是完整的海底世界。真把照片重建成高精度网格，那些多边形一个字节都不会进到成片里。

它做的是：**读懂这张照片的空间，用积木把这个空间搭回来。**

## 这条路线独有的好处

照片同时是两样东西：

- 挂给 Seedance 当 `@图片1`，锁材质、光线、色温、质感
- 反解成白模挂 `@白模1`，锁空间、运镜、节奏

**两者天然一致**——白模里的走廊长宽高，就是照片里那条走廊的长宽高。走产线 C（生成参考图）时永远要担心「参考图的构图会不会把镜头拽偏」，走这条路线不用担心，因为空间信息本来就是从这张图里量出来的。

## 五步

### 1. 叠网格读数

```bash
python3 engine/photo_grid.py 照片.jpg 照片-grid.jpg
```

它给照片叠 10×10 网格、三分线、中心十字，并把检测到的长斜线画出来。

**不要用肉眼估位置。** 同一张酒店走廊照片，我不叠网格估灭点是 0.40，叠上网格读出来是 0.51——差 0.11，换算成俯仰角就是 5°，白模的地面占比会整个不对。

也**不要信自动灭点检测**（脚本已经不给这个结论了）。那张走廊照片的地毯全是菱形花纹，45° 的长线压倒了真正的墙脚线，Hough 检出的「透视线」斜率清一色 ±1.0，算出来的灭点在 0.58-0.64。地毯、瓷砖、砖墙、格栅这类重复纹理的画面都会这样。

### 2. 读四个量

| 读什么 | 怎么读 |
|---|---|
| **灭点高度** | 顺着两侧墙脚线（或天花板线、路沿线）往远处延长，交点就是灭点。灭点 y = 0.50 → 镜头水平；< 0.50 → 上仰；> 0.50 → 俯视 |
| **相机高度** | 灭点那条水平线就是地平线。地平线穿过画面里站在地上的人的哪个部位，相机就在那个高度——穿腰就是腰高，穿头顶就是人眼高 |
| **实际尺寸** | 找把尺子：人 1.7m、门 2.1m、车高 1.5m、楼层 3m、车道宽 3.5m。用它换算画面里其他东西 |
| **焦段** | 先按场景猜：室内窄空间 24-35mm，街景 28-50mm，人像 50-85mm。**不用算准，第 4 步会收敛它** |

### 3. 搭出 scene.json

按 `scene-spec.md` 写。搭的时候只搭**会进画面的东西**，画外的一律不搭。

第一个 shot 就用 `static`，把机位参数填成第 2 步读出来的值，先不管运镜——这一步的目标只是「首帧长得像那张照片」。

在 `meta` 里留两行记录，方便别人（和三个月后的你）知道这些数是怎么来的：

```json
"sourcePhoto": "corridor.jpg",
"solvedFrom": "灭点在画面 y≈0.51 → 镜头基本水平；地面占下半幅 → 机位约 1.0m；两侧墙脚在画面底边接近出画 + 走廊宽约 3.2m → 焦距约 28mm"
```

### 4. 渲首帧，和照片并排看，改，再来

```bash
node engine/preview.mjs scene.json 0 t0.png
ffmpeg -y -i 照片.jpg -i t0.png -filter_complex "[0:v]scale=900:-2[a];[1:v]scale=900:-2[b];[a][b]vstack" 对比.jpg
```

一轮大约 30 秒。**两三轮就该收敛**，收敛不了通常是尺寸读错了（比如把 3.2m 宽的走廊读成 2.6m），回第 2 步重读，不要靠调焦段硬凑。

对齐到什么程度就停：**灭点位置、主要边线的收敛角度、地面与墙面的分界高度三样对上就够了。**

目标是「同一个空间」，不是「同一张图」。白模不提供材质和光线，像素级对齐没有意义——那些信息本来就要从照片本身继承。**再往下抠是在浪费时间。**

### 5. 加运动，然后才是运镜

到这一步空间已经站住了，剩下的和别的白模一样：

- 给主体排 `path`（主体必须动，杵着不动等于没给 AI 信号）
- 把第一个 `static` 换成真正的镜头序列
- `node engine/probe.mjs scene.json` 过体检
- 渲、抽帧自检、`make_prompt.mjs` 出 prompt

## 定向引用要这么写

照片路线的 prompt 有一处和别的不一样——**那张照片就是 `@图片1`**：

```
参考 @图片1 的：墙面材质、地毯图案、壁灯的光晕与色温、整体的明暗关系；
不从 @图片1 继承：构图和镜头位置（这两样由 @白模1 决定）。
```

看起来矛盾（白模就是从这张图反解的，构图当然一样），但这句话仍然要写。**它管的是「照片是静止的一帧，而片子要动」**——不写这句，模型容易把整段片子拍成一张会呼吸的照片。

## 什么照片适合，什么不适合

✅ **适合**：
- 有明确直线结构的（走廊、街道、房间、桥、楼梯、剧场）——透视线好读
- 空间尺度可推的（画面里有人、门、车这类已知尺寸的东西）
- 爽点在「谁在哪、镜头怎么走」的

❌ **不适合**：
- 纯特写、大头照、静物微距——没有空间可反解，直接走产线 C
- 自然景观没有直线参照的（森林、海面、云）——尺度无从推起，可以搭个大概但别指望对齐
- 爽点在手指细节、面部微表情、布料飘动的——白模帮不上，硬做只会暴露短板

## 多张照片

同一个场景的多个角度：挑**空间信息最完整的那张**做反解（通常是最广的那张），其余的挂给 Seedance 当额外的材质参考。

不同场景的多张照片：那是多个 scene，一个一个来。别试图在一个白模里塞两个空间——除非你真的要做一次转场，那就排成两个 shot，中间硬切。

## 实测记录

2026-08-17，一张 2560×1440 的酒店走廊照片（一点透视、暖色壁灯、菱形花纹地毯）：

| 轮次 | 改了什么 | 结果 |
|---|---|---|
| 1 | 灭点肉眼估 0.40 → 镜头上仰 4°，走廊 2.6m 宽，33mm | 透视骨架对了，但天花板死黑、走廊偏窄、视野偏紧 |
| 2 | 走廊放宽到 3.2m、改 28mm、修了向下面的补光 | 门的排列节奏和两侧收敛角度对上 |
| 3 | 叠网格重读灭点 = 0.51 → 镜头改成基本水平 | 地平线高度对齐，收敛 |

全程约 3 分钟。第 3 轮那个修正说明了一件事：**前两轮我一直在调焦段和宽度，其实错的是俯仰角**——不叠网格读数，就会在错的维度上一直调。
